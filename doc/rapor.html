Tickit Todo Uygulaması Teknik Raporu

Bu rapor, Tickit todo projesinin frontend, backend, veritabanı, güvenlik, API ve çalıştırma yapısını teknik olarak açıklar. Amaç, projeyi hiç bilmeyen bir geliştiricinin kodu okuyabilmesi, yerelde çalıştırabilmesi ve geliştirme yapabilmesidir.

Frontend: Next.js 16 + React 19 Backend: Express 5 Veritabanı: MongoDB + Mongoose Auth: JWT Bearer Token

1. Proje Özeti

Projenin amacı

Tickit, kullanıcıların kayıt olup giriş yaptıktan sonra kişisel görevlerini yönetebildiği full-stack bir todo uygulamasıdır. Kullanıcı görev ekleyebilir, düzenleyebilir, silebilir, tamamlandı olarak işaretleyebilir ve görevleri aktif/tamamlanan durumuna göre filtreleyebilir.

Frontend, backend, veritabanı ve deployment yapısı

  • Frontend: frontend/ klasöründe Next.js uygulaması yer alır. Varsayılan geliştirme portu 3000.
  • Backend: backend/ klasöründe Express API yer alır. Varsayılan port 5000.
  • Veritabanı: MongoDB bağlantısı backend/src/config/db.js dosyasında MONGODB_URI ile yapılır.
  • Deployment: Projede deployment konfigürasyonu yoktur. Frontend Vercel/Node host üzerinde, backend Render/Railway/Fly.io/VPS gibi Node çalıştırabilen ortamda yayınlanabilir.

Proje nasıl çalıştırılır?

# Backend
cd backend
npm install
npm run dev

# Frontend
cd frontend
npm install
npm run dev

Frontend API adresini frontend/.env.local içindeki NEXT_PUBLIC_API_URL ile okur. Backend MongoDB ve JWT ayarlarını backend/.env içinden okur.

6. Security Ayarları

Authentication ve authorization

  • Kullanıcı kayıt/giriş sonrası JWT alır.
  • Frontend token'ı localStorage.token olarak saklar.
  • Axios interceptor her isteğe Authorization: Bearer TOKEN header'ı ekler.
  • protect middleware JWT'yi doğrular, kullanıcıyı bulur ve req.user olarak request'e ekler.
  • Task route'larında router.use(protect) vardır; tüm task endpointleri auth ister.
  • Task update/delete/find işlemlerinde _id ile beraber user: req.user._id filtresi kullanılır. Bu authorization kontrolüdür.

Şifre hashleme

UserSchema.pre('save') hook'u password alanı değişmişse bcrypt.hash(password, 12) ile hash üretir. Login sırasında bcrypt.compare ile girilen şifre hash ile karşılaştırılır.

JWT/session/cookie kullanımı

Proje session veya cookie tabanlı auth kullanmaz. JWT response body ile frontend'e döner ve localStorage'da tutulur. Backend protect middleware içinde cookie token kontrolü için kod barındırır; ancak app içinde cookie parser middleware'i yoktur ve frontend cookie yazmaz.

CORS ve rate limiting

  • cors({ origin: process.env.CLIENT_URL || 'http://localhost:3000', credentials: true }) kullanılır.
  • /api altında 15 dakika için maksimum 100 istek sınırı vardır.
  • helmet() temel HTTP header güvenliği sağlar.

Input validation/sanitization

Mevcut validasyonun önemli kısmı Mongoose schema seviyesindedir: required, minlength, enum, unique. Frontend tarafında HTML required ve basit boş title kontrolü vardır. Ayrı bir validation library veya request sanitizer kullanılmamaktadır.

XSS, CSRF, SQL/NoSQL injection önlemleri

  • XSS: React metinleri escape ettiği için temel output XSS riski düşüktür. Ancak localStorage token XSS durumunda çalınabilir.
  • CSRF: Token localStorage + Authorization header ile gönderildiği için klasik cookie tabanlı CSRF riski daha düşüktür. Cookie auth'a geçilirse CSRF token gerekir.
  • SQL injection: SQL kullanılmadığı için klasik SQL injection yoktur.
  • NoSQL injection: Request body doğrudan create/update'e yayılır. Mongo sanitize middleware'i yoktur; production için express-mongo-sanitize önerilir.

Production için önerilen güvenlik iyileştirmeleri

  • JWT secret değerini uzun, random ve environment'a özel tutmak.
  • Token'ı localStorage yerine HttpOnly, Secure, SameSite cookie ile yönetmeyi değerlendirmek.
  • CSRF koruması eklemek, özellikle cookie auth'a geçilirse.
  • Request validation için Zod/Joi/express-validator eklemek.
  • NoSQL injection riskini azaltmak için request sanitizer kullanmak.
  • Rate limit'i endpoint tipine göre özelleştirmek; auth endpointleri için daha sıkı limit uygulamak.
  • Production'da error stack sızdırmamak, güvenli log altyapısı kurmak.
  • MongoDB Atlas IP allowlist ve minimum yetkili DB user kullanmak.

8. State Management ve Frontend Mimarisi

Component yapısı

  • DashboardPage: Görev state'i, filtre state'i, modal state'i, user state'i ve API CRUD işlemlerinin ana sahibi.
  • TaskForm: Controlled form state'i, açılır detay bölümleri ve submit payload üretimi.
  • TaskList: Boş liste mesajı veya task kartlarını render eder.
  • TaskCard: Tek görev görünümü, checkbox, edit/delete aksiyonları, priority/date chipleri ve renk vurgusu.
  • api.js: Merkezi Axios yapılandırması.
  • auth.js: localStorage token/user yardımcıları.

Hook kullanımı

  • useState: Form alanları, loading, modal, filtre, user ve tasks state'leri.
  • useEffect: Sayfa title ayarı, dashboard başlangıç auth kontrolü ve görev yükleme.
  • useRouter: Login/register/dashboard yönlendirmeleri.
  • useMemo: TaskForm içinde initial due date/time formatlama.

Form yönetimi

Formlar controlled component yaklaşımıyla yönetilir. Login/register formunda tek state objesi vardır. TaskForm daha kapsamlıdır: form state'i task payload alanlarını, openSections state'i açıklama/tarih/renk/önem panellerini tutar.

API istekleri

Tüm frontend API çağrıları frontend/lib/api.js içindeki Axios instance üzerinden yapılır. Base URL NEXT_PUBLIC_API_URL ile ayarlanır; yoksa http://localhost:5000/api kullanılır. Request interceptor token'ı header'a ekler.

Loading/error state yönetimi

  • Login/register submit sırasında loading true olur, buton disabled olur ve metin değişir.
  • Dashboard ilk açılışta loading ile yükleniyor mesajı gösterir.
  • Task create/update sırasında formLoading form submit butonunu disabled yapar.
  • Hatalar toast mesajlarıyla kullanıcıya bildirilir.

9. Hata Yönetimi ve Loglama

Frontend hata yönetimi

  • Login/register hatalarında API response mesajı varsa gösterilir.
  • Dashboard task yükleme, ekleme, güncelleme, silme ve tamamlama hataları için Türkçe toast mesajları vardır.
  • Axios response interceptor 401 aldığında token ve user localStorage değerlerini siler ve login'e yönlendirir.

Backend hata middleware'i

backend/src/middleware/errorHandler.js, yakalanan hataları console'a basar ve JSON response döndürür. NODE_ENV=development ise stack trace response'a eklenir.

Console/server log mantığı

  • MongoDB bağlantısı başarılı olursa host bilgisi loglanır.
  • Server başlarsa port URL'i loglanır.
  • Error middleware err.stack değerini console'a yazar.

Not: Next build sırasında workspace root/çoklu lockfile uyarısı görülebilir. Bu, proje üst dizininde ek bir package-lock.json algılanmasından kaynaklanır. Build başarıyla tamamlanabilir. Uyarıyı susturmak için next.config.mjs içinde Turbopack root ayarı yapılabilir veya gereksiz lockfile kaldırılabilir.

Veritabanı bağlantısı kurma

  1. MongoDB Atlas'ta cluster ve database user oluşturun.
  2. IP allowlist ayarını yapın.
  3. backend/.env içine MONGODB_URI ekleyin.
  4. URI içinde database adını belirtin: ...mongodb.net/tickit?appName=....
  5. Backend'i yeniden başlatın.

11. Eksikler ve Geliştirme Önerileri

Projede eksik kalan yerler

  • Backend testleri yok.
  • Frontend e2e veya component testleri yok.
  • Task kategori/tag alanı yok.
  • Server-side pagination yok; task listesi tamamen client'a gelir.
  • Görev arama özelliği yok.
  • Görev sıralama ve overdue durumu yok.
  • Hazır seed veya demo user yok.
  • backend/.env.example dosyası içerik olarak doldurulmalı.

Güvenlik iyileştirmeleri

  • Request validation library eklenmeli.
  • NoSQL sanitize middleware eklenmeli.
  • JWT localStorage yerine HttpOnly cookie + CSRF koruması değerlendirilmeli.
  • Auth endpointleri için daha sıkı rate limit uygulanmalı.
  • Password policy güçlendirilmeli.
  • Production loglama için structured logger kullanılmalı.

Performans önerileri

  • tasks collection için { user: 1, createdAt: -1 } index'i eklenmeli.
  • Görev listesi büyürse pagination veya infinite scroll eklenmeli.
  • Task update sonrası tüm listeyi yeniden almak yerine mevcut state güncellemesi şimdiki gibi korunabilir; ancak concurrency durumları için server snapshot düşünülebilir.
  • Next config içinde workspace root uyarısı temizlenmeli.

Kod kalitesi önerileri

  • API response tipleri ve form validasyonları için ortak schema tanımlanmalı.
  • TaskForm içindeki renk/önem sabitleri ayrı config dosyasına alınabilir.
  • Auth state için küçük bir context/provider eklenebilir.
  • Backend controller'larda allowlist update payload kullanılmalı; request body doğrudan modele verilmemeli.
  • Hata mesajları ve toast metinleri merkezi constants dosyasında toplanabilir.
